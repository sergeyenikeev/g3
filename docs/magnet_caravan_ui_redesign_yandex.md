# Magnet Caravan UI Redesign For Yandex Games

## 1. Ключевые проблемы текущего интерфейса

### Что перегружает новичка

- На первом экране одновременно конкурируют главный CTA, дейлик, обучение, миссии, мастерская, рейтинг, пилот и настройки.
- Мастерская открывается сразу как плотный каталог карточек с мелким текстом и равноважными решениями.
- Рейтинг выглядит как таблица со слишком большим количеством чисел, режимов и карьерных деталей для раннего этапа.
- Ранние rewarded-механики заметны слишком рано и мешают чистому первому запуску.

### Что мешает пониманию интерфейса

- Главный путь игрока не считывается за 3–5 секунд.
- Системные панели конкурируют с основным действием вместо того, чтобы поддерживать его.
- Мелкие подписи и длинные строки создают ощущение прототипа, а не законченного коммерческого продукта.
- Внутри workshop/leaderboard игроку сразу приходится принимать слишком много решений без приоритета.

### Что мешает монетизации

- Rewarded value не всегда подан через ясную формулу "что смотрю -> что получаю".
- Слишком ранний контакт с рекламными механиками повышает тревожность и снижает доверие.
- Workshop не подсказывает "лучший следующий шаг", поэтому игрок хуже понимает ценность болтов, ядер и ускорителей.
- Results / reroll CTA были функциональны, но недостаточно прозрачны по обещанию награды.

### Что критично для модерации Яндекс Игр

- Все зависимые от языка строки должны быть переведены и проходить через единый i18n-слой.
- UI не должен обрезаться, наезжать и ломаться в узких окнах.
- Rewarded-действия должны быть добровольными и однозначно маркированными.
- Игра не должна показывать браузерное выделение/контекстное меню на игровом поле.
- Игра не должна выглядеть "в разработке" из-за плотного, мелкого или визуально хрупкого интерфейса.

### Официальные документы, на которые опирается решение

- Quick start: https://yandex.com/dev/games/doc/en/concepts/quick-start
- Requirements: https://yandex.com/dev/games/doc/en/concepts/requirements
- SDK: https://yandex.com/dev/games/doc/en/sdk
- Add new game: https://yandex.com/dev/games/doc/en/console/add-new-game
- Monetization: https://yandex.com/dev/games/doc/en/services/about-monetization
- RU SDK / install: https://yandex.ru/dev/games/doc/ru/sdk/sdk-about#install
- RU requirements: https://yandex.ru/dev/games/doc/ru/concepts/requirements

### Соответствие ключевым платформенным ожиданиям

- Rewarded и interstitial должны открываться только после понятного действия пользователя и без маскировки под обычный gameplay-action.
- Для real-time flow реклама не должна ломать игровой ритм и не должна появляться как обязательный шаг на раннем этапе.
- Вся текстовая система должна быть устойчивой к смене языка и к разной длине строк.
- Главные UI-элементы должны оставаться читаемыми и помещаться в безопасной зоне на разных размерах окна.

## 2. Новая progression-модель интерфейса

### Stage A — новичок

Показываем:

- Один доминирующий CTA `Играть`.
- Одну вторичную кнопку `Обучение`.
- Компактный статус-бар с валютой.
- Один короткий stage-hint о базовом loop: собрать лом -> сдать в переработчик.
- Визуальный hero-preview только как поддержка атмосферы, не как источник новой информации.

Скрываем или деакцентируем:

- Мастерскую.
- Рейтинг.
- Дейлик.
- Миссии.
- Rewarded toggles, x2 results, reroll.
- Переименование пилота и второстепенные навигационные действия.

Продуктовая цель:

- Снять тревожность.
- Ускорить первый старт.
- Не превращать первый сеанс в рекламный funnel.

### Stage B — игрок втянулся

Показываем:

- `Играть` как главный CTA.
- `Ежедневка` как понятный вторичный CTA.
- Компактную версию мастерской.
- Упрощённый рейтинг с коротким топом и личным результатом.
- Нижний summary-блок с кратким прогрессом по liveops.

Раскрываем:

- Workshop только в сокращённой версии с ограниченным количеством полезных карточек.
- Leaderboard без фильтров и без длинного карьерного хвоста.
- Rewarded-ускорители только после того, как игрок уже понял базовый loop.

Продуктовая цель:

- Дать чувство роста.
- Подсветить первую meaningful meta-progression.
- Ввести мягкие добровольные рекламные бонусы без давления.

### Stage C — опытный игрок

Показываем:

- Полную навигацию.
- Полную мастерскую.
- Полный рейтинг с фильтрами, карьерным прогрессом и platform leaderboard summary.
- Все дополнительные системы.

Продуктовая цель:

- Дать глубину без потери контроля.
- Поддержать retention через цели, buildcraft и соревновательность.

### Реализованные пороги в коде

- `Stage A`: первые 1–2 сессии и очень ранний прогресс.
- `Stage B`: несколько запусков, но ещё ранняя/средняя мета.
- `Stage C`: устойчивый прогресс по сессиям, волнам и покупкам в мастерской.

Текущая эвристика хранится в [uiProgression.ts](/D:/p/g3/src/game/meta/uiProgression.ts:1) и может быть легко откалибрована позже аналитикой.

## 3. Переработка главного экрана

### Новая иерархия

- `Играть` — единственный визуально доминирующий CTA.
- Вторичный CTA зависит от стадии: сначала `Обучение`, потом `Ежедневка`.
- Workshop / Leaderboard убраны из первого впечатления и появляются позже.
- Маркетинговая строка заменена на короткий actionable hint по стадии.

### Что изменено в реализации

- В [MenuScene.ts](/D:/p/g3/src/game/scenes/MenuScene.ts:1544) добавлен stage-aware layout.
- Для `Stage A` скрываются top-nav элементы workshop/leaderboard/pilot.
- Utility panel в `Stage A` больше не показывает лишние продуктовые entry points.
- Rewarded start bonus больше не шумит на самом первом экране.
- Summary/liveops блок полностью убирается у новичка, чтобы экран не выглядел как dashboard.

### UX-обоснование

- Новичок быстрее понимает, куда нажать.
- Сокращается когнитивная нагрузка.
- Первый экран больше не выглядит как "панель из режима liveops".

## 4. Переработка мастерской

### Новая модель раскрытия

- `Stage A`: только 4 базовых апгрейда, один clear recommendation, крупные карточки в одну колонку.
- `Stage B`: 8 наиболее полезных апгрейдов, две колонки, выше плотность, но ещё без полного каталога.
- `Stage C`: полный набор апгрейдов, более плотная сетка для опытного игрока.

### Что изменено в реализации

- Workshop теперь использует stage-aware visible set и order priority.
- Вверху блока появился `Best next step / Лучший следующий шаг`.
- Видимость карточек считается через [uiProgression.ts](/D:/p/g3/src/game/meta/uiProgression.ts:1).
- Layout workshop больше не держится на одной fixed-сетке для всех игроков.
- Плотность карточек зависит от стадии: 1 колонка -> 2 колонки -> 3 колонки.

### Почему это лучше для UX и монетизации

- Игроку не предлагают 10+ одинаково важных решений сразу.
- Повышается вероятность первой осмысленной покупки.
- Visible progress в workshop помогает игроку понимать ценность болтов и ядер.
- RV не навязывается внутри workshop, а meta-value растёт за счёт ясности следующего шага.

## 5. Переработка рейтинга

### Новая модель раскрытия

- `Stage A`: рейтинг полностью скрыт.
- `Stage B`: короткий рейтинг, 3 строки, личный результат, следующий дивизион.
- `Stage C`: полный рейтинг с фильтрами, карьерными milestone и platform summary.

### Что изменено в реализации

- В [MenuScene.ts](/D:/p/g3/src/game/scenes/MenuScene.ts:2683) leaderboard стал stage-aware.
- Для ранней версии скрываются фильтры, milestone-блок и platform summary.
- Список записей сокращён до 3 строк для `Stage B`.
- Текст строки упрощён: меньше цифр, меньше шума, выше считываемость.

### UX-обоснование

- Ранний рейтинг работает как мотивационный social proof, а не как пугающая таблица.
- Игрок видит личный результат и ближайшую цель, а не полный объём метаданных.

## 6. Типографика и layout

### Новые принципы

- Главные CTA крупнее и чище.
- Secondary copy короче и stage-specific.
- Workshop и leaderboard больше не пытаются использовать одну и ту же плотность на всех стадиях.
- Убрано блокирование zoom через viewport meta, чтобы не падать в accessibility anti-pattern.

### Технические выводы

- Старая проблема была не только в размере шрифта, а в количестве сущностей на экран.
- Поэтому решение строится через progressive disclosure, а не просто через mechanical scale-up.
- Для Yandex moderation это снижает риск мелкого текста, наложений и ощущения unfinished UI.

### Текущее исправление

- `index.html` больше не использует `maximum-scale=1` и `user-scalable=no`.
- Main menu, workshop и leaderboard теперь сильнее завязаны на адаптивную плотность, а не только на scale контейнера.

## 8. RV / монетизация

### Новая продуктовая логика

- В `Stage A` rewarded не должны быть частью первого впечатления.
- В `Stage B` rewarded открываются как понятные добровольные ускорители.
- В `Stage C` rewarded могут работать как полноценный слой liveops/retention.

### Что уже изменено

- `x2` на results скрыт у новичка в [ResultsScene.ts](/D:/p/g3/src/game/scenes/ResultsScene.ts:79).
- `reroll` на upgrade pick скрыт у новичка в [UpgradeScene.ts](/D:/p/g3/src/game/scenes/UpgradeScene.ts:47).
- Меню больше не показывает early rewarded-start шум в `Stage A`.
- Формулировки CTA стали прямыми:
  - `WATCH AD & GET x2 WORKSHOP REWARD`
  - `WATCH AD FOR NEW PICKS`
  - `WATCH AD & REVIVE`
  - RU-аналогичные формулировки добавлены.

### Почему это повышает конверсию

- Reward понятен до клика.
- Игрок не чувствует себя пойманным в ad trap.
- Добровольный бонус появляется после того, как core loop уже стал ценным.

## 9. SDK / технические исправления

### Что уже было в порядке

- Runtime уже использует Yandex adapter, `LoadingAPI.ready()` и gameplay hooks.
- Yandex build pipeline уже умеет инжектить `/sdk.js` в release output.
- В [main.ts](/D:/p/g3/src/main.ts:7) уже есть блокировка `contextmenu`, `selectstart` и `dragstart`.

### Что важно зафиксировать

- Для publish build необходимо сохранить current release injection `/sdk.js` в HTML архива.
- Rewarded / interstitial должны продолжать вызываться только через platform adapter.
- Boot/runtime fallback должен оставаться продуктовым: без сырых stack traces и с понятным CTA на перезапуск.
- Playfield shell должен продолжать жёстко блокировать browser context menu, selection и жесты, которые ломают игровой input.
- Нужно отдельно прогнать smoke-test внутри черновика Яндекс Игр после сборки `build:yandex` / `package:yandex`.
